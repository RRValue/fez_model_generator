## Overview

Move the FEZ → OBJ converter to a vcpkg-based C++26 build (Visual Studio 18 2026 generator), restructure the code
into a layered, testable `fez_core` library plus a `fez_model_generator` CLI, and add Catch2 tests. Phase 0 builds a
safety net (new build + byte-exact golden comparison against the current program's output). Phase 1 restructures
without changing a single output byte. Phase 2 fixes known bugs, one deliberately output-changing step at a time.

## Architecture Decisions

- **vcpkg classic mode** with the vcpkg root given by the CMake cache variable `VCPKG_FEZ_MODEL_BASE` (prebuilt
  `assimp`, `eigen3`, `catch2`, triplet `x64-windows`); no `vcpkg.json`. No `VCPKG_ROOT` environment variable is
  needed: the top-level `CMakeLists.txt` checks `VCPKG_FEZ_MODEL_BASE` before `project()` and sets `VCPKG_ROOT`
  (CMake variable and `ENV{VCPKG_ROOT}`) and `CMAKE_TOOLCHAIN_FILE` from it. It is set in `CMakeUserPresets.json`
  or with `-DVCPKG_FEZ_MODEL_BASE=<path>`. Qt 6 comes from the local Qt install via `CMAKE_PREFIX_PATH` in the gitignored
  `CMakeUserPresets.json`; a committed `CMakeUserPresets.example.json` documents the expected entries.
- **Presets for a multi-config generator:** one configure preset `windows-vs` (`build/windows-vs`, generator
  `Visual Studio 18 2026`, `x64`), build/test presets `windows-debug` and `windows-release`. (Refines the spec's
  "configure presets per config": VS is multi-config, so one configure preset is enough.) Binaries land in
  `build/windows-vs/bin/<Config>/`.
- **QtConcurrent stays** for parallelism: `QtConcurrent::blockingMapped` on a pipeline-owned `QThreadPool` sized by
  `--jobs`.
- **CLI arguments arrive in Phase 0** (Task 2), earlier than the spec's Phase 1 step 1, so the golden test can drive
  the program headlessly and the reference can be generated by the same binary type the tests run. The output
  layout is unchanged.
- **Golden reference is versioned outside the repo**, e.g. `Z:/fez_data/golden/v1`; every deliberate output change in
  Phase 2 produces `v2`, `v3`, … and `FEZ_GOLDEN_DIR` is pointed at the newest. Old versions are kept.
- **Golden test is its own CTest entry** (`add_test` running `fez_tests "[.golden]"`, label `golden`) because
  `catch_discover_tests` does not register hidden tests.
- **Namespace `fez`** is introduced in one mechanical task (Task 8) instead of piecemeal, to avoid mixed qualification.
- **`--jobs` defaults to `QThread::idealThreadCount()`** rather than the spec's `std::thread::hardware_concurrency()`:
  the pool is a `QThreadPool`, and this is the value it would pick itself.
- **Tests run inside a `QCoreApplication`:** `fez_tests` has its own `main` (links `Catch2::Catch2`, not
  `Catch2WithMain`) that constructs a `QCoreApplication` before `Catch::Session::run`. Tests use `QProcess`,
  `QImage` and `QtConcurrent`, which are only reliable with an application object.
- **Byte-identity includes which files exist.** Today a level fails as a whole when any section element is missing or
  any referenced asset fails, and the writer emits one mesh and one material per instance (no deduplication). Phase 1
  preserves these rules explicitly; they decide which files and material entries appear in the output.

## Common Commands

| Purpose | Command |
|---|---|
| Configure | `cmake --preset windows-vs` |
| Build | `cmake --build --preset windows-debug` |
| All default tests | `ctest --preset windows-debug` |
| Focused tests | `build\windows-vs\bin\Debug\fez_tests.exe "[tag]"` |
| Golden test | `ctest --preset windows-debug-golden` or `windows-release-golden` (needs `FEZ_DATA_DIR`, `FEZ_GOLDEN_DIR`; see Task 5) |
| Run converter | `build\windows-vs\bin\Debug\fez_model_generator.exe --input <export> --output <fresh dir> [--only ao,ts,lv] [--jobs N] [--verbose]` (exit 0 all converted, 1 any asset failed, 2 usage error) |

The converter must always write into a **fresh, empty** output directory: `QFile::copy` does not overwrite, so stale
textures would hide differences.

  `Result<T> = std::expected<std::shared_ptr<const T>, Error>`; `Loaders` holds three `std::function`s

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| vcpkg assimp differs from the old RVDep assimp (OBJ header, number formatting) | High | Reference generated by the old code built against vcpkg assimp (Tasks 1–3). Never compare against old RVDep output. |
| Nondeterministic output from parallel runs | High | Task 3 two-run comparison; every output file has a single writer; always export into fresh directories. |
| `/std:c++latest` + Qt 6.11 / Eigen header issues on MSVC 18 | Medium | Task 1 fails fast; third-party headers as external includes; fall back to `CMAKE_CXX_STANDARD 23` only for a blocking compiler bug (document it). |
| Qt (msvc2022 build) vs. VS 18 toolset ABI | Low | MSVC v14x is binary compatible; verified by Task 1 manual run. |
| Hand-written mini fixtures diverge from real FEZ XML | Medium | Golden test on real data remains the authority; fixtures follow the element/attribute names the parsers read. |
| Golden test runtime (full export) | Low | Opt-in label `golden`; run at checkpoints and before commits touching core code. |
| `QFile::copy` no-overwrite hides stale textures | Medium | Fresh temp dirs in all tests; policy revisited in Task 32. |
| Blocking on `shared_future` inside `QThreadPool` workers reduces parallelism | Low | Loads run on the requesting thread (no deadlock); only waiting threads idle briefly. |
| NPC textures are named `<npc>/<action>.ani.png`, so their copy destination has a nested directory that `Writer::save` creates with `QDir::mkdir(".")`; these copies may fail silently today | Medium | Phase 1 reproduces the behavior unchanged (golden decides). Task 32 surfaces the failures; fixing them adds files to `lv_export/` and therefore requires a new golden version. |
| `exported/` side effect in the input tree (until Task 16) | Low | Golden and mini tests never use a committed or reference directory as `--input` directly (Task 7 copies the fixture); comparisons only cover the output root. Resolved by Task 16; both tests now assert the input stays untouched. |
